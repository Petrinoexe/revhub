# Что дальше, по порядку

Порядок не случайный: каждый пункт опирается на уже проверенное предыдущим.

## Этап 1 — довести до рабочего одного узла (сейчас)

- [x] модель, валидация, генератор `xray.json` (проходит `xray -test`)
- [x] генератор `wg-*.conf` + `apply.sh` / `rollback.sh`
- [x] клиенты, подписка `/sub/<token>`, dry-run маршрутов
- [ ] рендер нескольких туннелей сразу на одном узле и проверка, что метки не пересекаются
- [ ] `apply` из UI с подтверждением (сейчас применение — только руками на узле)
- [x] авторизация панели (пароль + cookie), подписка остаётся публичной
- [x] установщик (`revhub install`): бинарь, ядро, wireguard, юниты, админ, клиент
- [x] `install.sh` одной командой через curl: интерактивно спрашивает IP, порты и
      TLS, ставит зависимости, добывает бинарь (релиз или сборка из исходников),
      настраивает сертификат, включает сервис и печатает логин/пароль/адрес
- [x] TLS: reality / домен через ACME / самоподписанный на IP с пином; панель по HTTPS
- [ ] `xray -test` как часть `/api/render` (сейчас проверяется отдельной командой)

## Этап 2 — измерить то, что обещано

- [ ] стенд: 15 клиентов в одном процессе xray на локальной машине
- [ ] UDP/QUIC через WG-туннель и через VLESS-туннель — сравнение
- [ ] потери по классам под нагрузкой, rekey/реконнект WG, время восстановления
- [ ] учёт трафика: `xray api statsquery` по тегам против реально переданного

Без этих чисел не трогаем ни масштабирование, ни «оптимизации».

## Этап 3 — вторая машина

- [x] доставка артефактов на выходной по SSH (`revhub` сам ставит и применяет)
- [x] мониторинг узлов: статус, задержка, возраст handshake WG, `mgmt_via`
- [x] TLS по домену на выходном: acme.sh запускается на самом узле (шаг ACME)
- [x] TLS на голый IP через Let's Encrypt (shortlived, HTTP-01) + самоподписанный
- [ ] продление IP-сертификата без рестарта ядра (hot-reload вместо restart)
- [ ] отзыв/ротация ключа хоста SSH из UI (сейчас TOFU: первый ключ запоминается)
- [ ] healthcheck туннеля (`wg show` + пробный запрос через тег) и отображение в UI

## Этап 4 — то, что просил, но не в MVP

- [ ] AmneziaWG как замена WireGuard на плече через границу (тот же интерфейс, другой бинарь)
- [ ] reverse-VLESS (штатный Xray) как второй вид туннеля — там сохраняется IP клиента
- [ ] авторизация панели (сейчас только loopback без пароля — это осознанно)
- [ ] статистика по клиентам с историей и лимитами

## Чего сознательно не будет

Биллинг, Telegram-бот, мультиадмин, поддержка всех протоколов xray. Это
превращает «легче 3x-ui» в 3x-ui.
